Bitweb Core 31.3 is now available.
This is a maintenance release featuring backports from Bitcoin Core on top of the 31.x branch.

> ⚠️ **IMPORTANT! ALWAYS BACK UP YOUR WALLET DATA BEFORE ANY UPDATE.**
> Shut down your wallet completely, then copy your `wallet.dat` file to a safe place before
> updating. If possible, always encrypt your wallet with a strong password.

## Upgrade from 31.2

If you are already running Bitweb Core 31.2, upgrading to 31.3 is straightforward:

1. Shut down your node completely.
2. Back up your `wallet.dat` to a safe location outside the data directory.
3. Install Bitweb Core 31.3.
4. Start the node — it will continue syncing from where it left off.

No rescan or migration is required when upgrading from 31.2.

## What's new in 31.3

### Chain sync metadata refreshed to height 107900

Minimum chain work, `assumevalid`, the checkpoint list and the AssumeUTXO entry have been
updated to block **107900** (previously 69000), together with the built-in chain transaction
statistics used for sync-progress estimates. A new node therefore skips script verification for
a much larger part of the chain during initial sync, and the progress estimate is more accurate.
Consensus rules are unchanged. The bundled `asmap` data (`ip_asn.dat`) was also refreshed.

### Private broadcast hardening (`-privatebroadcast`)

- The feature is now explicitly marked **experimental** in `-help` and in the
  `sendrawtransaction` RPC documentation. It provides best-effort concealment of a
  transaction's origin.
- The private broadcast queue is now **bounded at 10,000 transactions**. When it is full,
  `sendrawtransaction` fails with the new RPC error code `-37` (`RPC_LIMIT_EXCEEDED`)
  instead of growing without limit. Re-submitting a transaction that is already queued is
  still a harmless no-op.
- The stale-transaction re-check no longer holds `cs_main` for the whole batch, only for
  each single transaction. This removes a potential source of lock contention.

### Network and P2P fixes

- **Only the misbehaving peer is disconnected.** Previously, a misbehaving peer caused
  *every* connection from the same IP to be dropped (for example, all peers behind a shared
  Tor exit node). Now only that one connection is closed. Discouragement by address is
  unchanged.
- **Stuck send buffers are cleaned up.** A peer whose send buffer stays full for longer
  than the standard 20-minute inactivity timeout is now disconnected.
- **Duplicate transaction announcements are ignored.** Repeated txid/wtxid entries inside a
  single `inv` message are now de-duplicated, which reduces wasted work from spammy peers.
- **Seed nodes are assumed to support BIP324.** Addresses from DNS and fixed seeds are now
  assumed to support the v2 encrypted transport. If a peer does not, the node simply
  reconnects with v1.
- The new IPv6 documentation range `3fff::/20` (RFC 9637) is now treated as non-routable
  and is not stored or relayed as a valid address.

### Large file handling

Block file seeking, truncation and allocation now use 64-bit offsets throughout
(`flatfile`, `AutoFile`, `TruncateFile`, `AllocateFileRange`). This removes potential
overflows on files above 2–4 GiB, particularly on Windows where `long` is 32-bit.

### Version bits warnings (BIP 323)

Only version bits 0–4 are now used for "unknown new rules activated" warnings.
Bits 5–28 are ignored for soft-fork signalling and warnings, per
[BIP 323](https://github.com/bitcoin/bips/blob/master/bip-0323.mediawiki). This avoids
false alarms when miners use these bits for other purposes.

### Configuration and documentation

- `-proxy=addr:port=NETWORK` is now parsed and documented from a single list of network
  names (`ipv4`, `ipv6`, `onion`, `cjdns`), so the help text and the parser can no longer
  diverge. `doc/tor.md` was corrected to use `onion` instead of `tor`.
- Updated man pages and the `bitweb.conf` example (new `assumevalid` hash).

### Build and developer changes

- CMake: `include_directories()` replaced by `target_include_directories()`, and the
  `WarnAboutGlobalProperties` module removed. This fixes the `-Wnon-target-directive`
  warning on CMake 4.5+.
- Fixed an unused-private-field warning on Clang 24 (`memusage`).
- New and updated tests: private broadcast cap, transaction INV de-duplication, pruned
  stale-fork handling, versionbits warnings, `-proxy` networks; fuzz harnesses adapted.

### Carried over from 31.2

The header PoW verification cache (`-headerpowcachesize`), the parallel header PoW check queue
and the backported fixes from the 31.2 release remain unchanged.

See [release notes](https://github.com/bitweb-project/bitweb/blob/master/doc/release-notes/release-notes-31.3.md) on GitHub for the full changelog.

## Troubleshooting

- **Node won't start after upgrade** — make sure you're upgrading from 31.x (or a migrated 30.x
  wallet). If you're coming from an older, unmigrated chain, instructions in the [30.3.1](https://github.com/bitweb-project/bitweb/releases/tag/v30.3.1) release.
- **Balance shows zero after upgrade** — run `bitweb-cli rescanblockchain` to rescan the chain.
